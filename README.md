# RiskCube MCP Pricing Server

This project implements an explainable, typed MCP pricing service for structured equity-linked products. It follows the attached `InstrumentKey`, `UnwindMapRaw`, `RiskFactorKeys`, `MarketDataSnapshot`, `UpdatedLifecycle`, `SensitivityResults`, and `RiskCube` contract, and is managed with `uv`.

## Important model scope

The engine is a transparent risk-neutral **GBM Monte Carlo** implementation intended as a deterministic reference and test harness. It supports vanilla puts/calls, knock-in and knock-out barriers, global or observation-date-scoped barrier metadata, autocall/FCN-style accrual, memory coupons, lifecycle fixings, adjustment factors, FX conversion, and common-random-number finite-difference risk. Smooth vanilla paths use the tested `QuantLib-Risks`/XAD tape backend; discontinuous barrier, knock-in/knock-out, autocall, and memory-state risks are reported as common-random-number finite-difference event-state estimates unless a dedicated discontinuity-aware AAD method is configured.

The output contains both numerical results and an `explainability` object. The latter records the model, number of paths and steps, time to expiry, moneyness/state classification, observed barrier events, lifecycle state, applied fixings, and coupon-memory carry. Every RiskCube cell includes the originating RFK, sensitivities, method, and bump size.

## Setup

```bash
uv sync --dev
uv run pytest -q
uv run ruff check .
uv run mypy src
```

The project requires Python 3.11 or newer. `uv` creates and maintains `.venv` and `uv.lock`; do not install project dependencies into the system interpreter.

## Run as an MCP stdio server

```bash
uv run riskcube-mcp
```

A client configuration can launch the server with `uv run --directory /absolute/path/to/riskcube-mcp riskcube-mcp`. The exposed tool is named `pricing_and_sensitivity` and accepts one JSON object with the five attached input sections plus `parameters`.

## Python API

```python
from riskcube_mcp import PricingRequest, sensitivity

request = PricingRequest.model_validate(payload)
result = sensitivity(request)
print(result["PV"])
print(result["RiskCube"])
```

## Test data

`data/scenarios.jsonl` contains 96 deterministic cases generated by `data/generate_scenarios.py`. The matrix covers:

| Dimension | Values |
|---|---|
| Moneyness | OTM, ATM, ITM |
| Time horizon | Near expiry, far expiry |
| Barrier configuration | None, global up-KO, local down-KI, local up-KO |
| Memory | Enabled, disabled |
| Accrual | Enabled, disabled |

Each case also includes Spot, Volatility, InterestRate, and FXSpot RFKs. The suite uses low path counts for fast CI; production calibration should increase paths, steps, and independent seeds, and should be benchmarked against a validated library implementation.

## Financial interpretation

For a put, a spot increase generally reduces delta and an increase in volatility generally increases option value, subject to barrier-event effects. A knock-in payoff is zero until the barrier event occurs, while a knock-out payoff is replaced by its rebate after the event. A memory coupon carries unpaid coupon accrual forward and releases it when the observation becomes eligible. The diagnostics deliberately expose these state transitions rather than presenting an opaque scalar.

## AAD and sensitivity policy

For smooth vanilla paths, the service uses **QuantLib-Risks/XAD** with `xad.adj_1st.Tape`, registering spot, volatility, rates, and dividend inputs and propagating adjoints from the NPV. The native analytic engine supplies gamma and theta, and the RiskCube emits the full stable vector including `delta`, `gamma`, `vega`, `rho`, `theta`, `fx_delta`, `vanna`, `volga`, and `charm`. Barrier, knock-in/knock-out, autocall, and memory-coupon products use common-random-number finite differences for discontinuous event-state transitions. The method is reported separately in each cell; the service does not mislabel finite differences as AAD.

## Streamable HTTP

The same MCP server supports both transports:

```bash
uv run riskcube-mcp                         # stdio
uv run uvicorn riskcube_mcp.server:app      # Streamable HTTP at /mcp and /healthz
```

The HTTP application includes MCP lifespan startup, a `/healthz` readiness route, and explicit host protection. Set `ALLOWED_HOSTS` in production to the exact deployment host(s), for example `ALLOWED_HOSTS=my-project.vercel.app,my-project-git-main-user.vercel.app`. Local development defaults include localhost and Vercel preview domains.

## Vercel deployment

The repository includes `api/index.py`, `vercel.json`, and `[tool.vercel] entrypoint = "api.index:app"`. Vercel loads the ASGI app and routes `/api` to the MCP endpoint; the rewrite in `vercel.json` also maps `/mcp` to `/api`. Deploy from the repository root with the Vercel CLI or by importing the repository into Vercel. Configure `ALLOWED_HOSTS` as a Vercel project environment variable and use a deployment-specific exact host in production rather than relying on the preview wildcard.

## Production Vercel deployment

This repository is deployable as a Vercel Python ASGI function. The entry point is `api/index.py`, which exports the Streamable HTTP application from `riskcube_mcp.server`. Vercel routing maps `/mcp` and `/mcp/*` to the function, while `/healthz` returns a lightweight readiness response.

Deploy from the repository root with:

```bash
uv sync --dev
vercel deploy --prod
```

Configure `ALLOWED_HOSTS` in Vercel Project Settings. Use a comma-separated list containing the Vercel deployment hostname and any custom domain, for example `fina-pricer.vercel.app,api.example.com`. Keep the default development allowlist out of production. The MCP client endpoint is `https://<deployment-host>/mcp`; the readiness endpoint is `https://<deployment-host>/healthz`.

The serverless function is intentionally stateless. Send the complete pricing request in each MCP tool call, including market snapshot, lifecycle state, fixings, RFKs, model parameters, path count, and seed. Do not rely on local files or process memory for positions, credentials, or market data. Set a conservative path count and step count for serverless latency, and use a separately hosted pricing worker for large production portfolios.

The deployment package includes `pyproject.toml`, `uv.lock`, `api/index.py`, `src/riskcube_mcp/`, `vercel.json`, and `.vercelignore`. Development tests, probes, and local virtual-environment files are excluded from the Vercel upload.
